# Specification — MVP

WHAT과 WHY에 집중한다. HOW는 plan.md에서 다룬다.

## 유저 스토리

- As a 로봇 관심자, I want 전 세계 휴머노이드 로봇을 한 목록에서 보고, So that 어떤 로봇들이 있는지 한눈에 파악한다.
- As a 사용자, I want 이름·제조사·국가·용도로 검색/필터하고, So that 관심 있는 로봇을 빠르게 찾는다.
- As a 사용자, I want 로봇 상세 정보(스펙, 이미지, 출처)를 보고, So that 깊이 있게 비교한다.

## 기능 요구사항 (MVP)

### FR-1 로봇 목록
- 로봇을 카드 그리드로 표시 (이미지, 이름, 제조사, 국가)
- 데이터 출처에 관계없이 통합된 형태로 노출

### FR-2 검색 / 필터
- 텍스트 검색: 이름, 제조사
- 필터: 국가, 용도/카테고리, 상태(연구용/상용/콘셉트)
- 검색은 빈 결과 시 안내 메시지 표시

### FR-3 로봇 상세
- 전체 스펙(키, 무게, 자유도, 발표연도 등), 설명, 이미지 갤러리
- 출처 URL 및 수집 시각 표기
- AI 검색으로 채워진 미검증 필드는 시각적으로 구분

## 데이터 모델 (개념)

`Robot`: id, name, manufacturer, country, year, category, status, height, weight, dof, description, images[], sources[]{url, fetchedAt, verified}

## 성공 기준

- 시드 데이터로 목록/검색/상세가 동작
- 새 로봇을 데이터 소스에 추가하면 코드 변경 없이 목록에 반영
- 스크래핑/AI 수집 결과가 동일 `Robot` 스키마로 들어옴

## Clarifications

### 2026-05-23

- **데이터 범위 (MVP)**: 수동 시드 JSON + 실제 제조사/위키 스크래핑 어댑터 1종까지 MVP에 포함한다. (AI 검색 어댑터는 인터페이스만 두지 않고, 아래 수집 방식으로 대체)
- **AI 검색 방식**: 런타임 LLM/검색 API를 호출하지 않는다. 대신 **Claude Code가 큐레이션 시점에 직접 웹을 조사**해 결과를 JSON에 추가한다. 따라서 `@anthropic-ai/sdk` 등 런타임 의존성은 없으며, AI로 수집한 항목은 `sources[].verified=false`로 표기한다. (즉 "ai-search"는 런타임 코드 모듈이 아니라 사람+Claude Code의 데이터 보강 절차)
- **데이터 영속성**: 스크래핑·AI 수집 결과를 `data/` 아래 JSON으로 저장하고 git에 커밋한다. 빌드 시 정적으로 포함되며, 런타임 DB는 두지 않는다. (인터페이스는 추후 DB 교체 가능하게 유지)
- **UI 언어**: 한국어/영어 i18n을 처음부터 지원한다. 로봇 이름·제조사 등 고유명사는 원문(영문)을 유지한다.
